## Merged-cell period loss (root cause + fix) — pushed to fork main
Root cause: departments write a double/triple period as ONE merged cell
(e.g. `B195:C195='OOPS(T) 217'`). `XLSX.utils.sheet_to_json` returns only the
merge's top-left cell, so hidden periods were dropped: ACSE lost 498 of 1642,
II AIML-J Monday showed 5 of 8. Affected ACSE, CSE, SASH, BT, BI.
Fix: `sheetGrid(wb, sheetName)` in scripts/compile_all_workbooks.cjs expands
`!merges` into a row-major grid; 4 call sites swapped. Offset gotcha: xlsx
`!merges` indices are absolute (A=0) but sheet_to_json arrays are offset by the
sheet's start column (SASH sheets start at col B) — subtract first used row/col.
Verified against /tmp/gs.xlsx (authoritative ACSE, 1523 merges): 1642==1642.
Compiled dataset 4029 -> 4831 entries, 141 groups. Commit 766f710 on fork main
(rebased onto origin/main after it moved to 3756224).

Genuine source data facts (NOT bugs):
- `II MTECH(DS)` workbook sheet has zero periods filled (only BREAK/LUNCH) -> legitimately empty; test now asserts 0.
- BT/BI/M.Tech sections have 5 teaching days (Saturday = "ACTIVITIES").
- X-stream SEC-07/SEC-10 both list VBTF-04 FRI 08:15 in the source -> genuine clash.
- 132 room-clash / 83 faculty-clash slots are pre-existing source clashes (was 73 room before; expansion restored more real entries).
